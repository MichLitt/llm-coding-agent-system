# Improvement Plan v0.8.1-swe-harness — SWE-bench harness 短板修复

**状态：** In progress  
**计划日期：** 2026-10-30  
**当前代码版本：** agent `07eae78`（含 consecutive 重试策略、doom-loop 顺序修复）  
**上一阶段证据：** `WP1_RESULTS_2026-10-28.md`（正式实验）、`WP1_DEV_RETRY_POLICY_2026-10-29.md`（开发检查，GLM 与 DeepSeek）  
**计划目标：** 修复 WP1 暴露的 harness 短板，在新的开发集上用两个种子验证整体改动是否有提升；有提升再做消融、GLM 复核和留出集预注册。

> 原则：协议与健壮性修复对两组同时生效；改变 Agent 行为的改动全部放在运行级开关后面，默认关闭，C3 默认行为不变。开发集与确认集分开，确认集在本阶段不得使用。

## 0. 证据：短板在哪里

| 短板 | 证据 |
|---|---|
| 把正常探索当成失败 | 累计计数的重试保护在 GLM 上停掉 40–50% 的运行，85–90% 并非失败循环；改为连续计数后 GLM 开发集 +8.0 pp（p = 0.028）。同一个"非零退出"信号还驱动纠错提示、单文件编辑锁和 doom-loop 提醒；`set -o pipefail` 让 `grep … \| head` 的无匹配和 SIGPIPE（141）也算失败。 |
| 提示词不适合修 bug | 系统提示词为从零写代码的任务而写：要求"只为明确要求的行为写测试"、"ImportError 先装包"（SWE-bench 容器断网）、"每个文件最多重试 3 次后放弃"。SWE-bench 任务提示没有工作流程。mini-SWE-agent（有工作流程）在两个模型上都高于我们的基线：GLM 70 对 61.5，DeepSeek 64 对 54.5。GLM 候选组"自行结束但未解决"从 12 次增至 33 次。 |
| 没有步数预算意识 | DeepSeek 基线 20%、候选 35% 的运行跑满 40 步，许多是空 patch；放开重试保护后，DeepSeek 上被放出的运行 63% 撞上步数上限（GLM 约 23%）。 |
| 上下文管理实际未生效 | 工具输出压缩在配置中关闭；按 token 截断永远不触发（`add_message` 的调用方从不传 usage，计数停在系统提示长度）；语义压缩只在 `semantic` 模式启用。命令输出与整文件读取无上限进入上下文。截断代码若被触发，会从最前面删掉任务描述，也会拆散工具调用与结果。 |
| 消息协议没有校验 | doom-loop 提醒曾插在工具调用与结果之间，GLM 默默接受，DeepSeek 返回 400 后才发现（已在 `36d6300` 修复）。单次回复的工具调用无上限（正式实验中出现过一次 762 个）。 |

待补充：WSL 上的只读轨迹统计（非零退出的类别占比、纠错提示与编辑锁次数、最后一次修改后是否验证、每步上下文大小、大输出与整文件读取次数）。数据回来后追加到第 6 节，并据此调整第 3 节的取值。

## 2. H0 协议与健壮性（两组共同生效）

| 编号 | 改动 | 文件 | 验证 |
|---|---|---|---|
| H0.1 | 发请求前校验消息序列：每个带 `tool_calls` 的助手消息后面紧跟每个调用的工具结果，且没有孤立的工具结果；违反时抛出明确错误，而不是等供应商返回 400 | `core/context.py`、`core/agent_loop.py` | 单元测试：合法、插入消息、缺结果、孤立结果 |
| H0.2 | 历史 token 计数改为按字符估算当前上下文大小（每条消息各自估算），截断真正可用 | `core/context.py` | 单元测试：计数随消息增长、与真实请求无关 |
| H0.3 | 截断按"工具调用 + 结果"整组删除，始终保留第一个助手回合之前的任务消息，截断提示放在任务消息之后 | `core/context.py` | 单元测试：截断后序列仍合法、任务保留 |

H0 只在历史超过 180k（估算）token 或历史已经不合法时改变行为；WP1 运行中两者都未出现过（待第 6 节数据确认）。

## 3. H1 行为改动（运行级开关，默认关闭）

| 编号 | 开关（`--experiment-config`） | 候选取值 | 作用 |
|---|---|---|---|
| H1.1 | `error_signals` | `"semantic"` | 没有任何输出的非零退出和 SIGPIPE（141）视为探索结果，不算失败：不计入重试、不触发纠错提示、编辑锁和 doom-loop 提醒 |
| H1.2 | `edit_lock` | `false` | 关闭"出错后只能改一个文件"的限制 |
| H1.3 | `prompt_profile` | `"swebench"` | 换用修 bug 专用系统提示词：定位 → 复现 → 修复 → 验证 → 边界 → 清理；说明非零退出不一定是错误、输出会被截断、环境断网、步数有限；去掉"装包""3 次放弃""只为要求写测试"等规则 |
| H1.4 | `step_budget_notices` | `true` | 剩余 30%（至少 5 步）时提醒"还没改源码就现在改"，剩余 4 步时提醒"验证一次并结束，当前工作区就是答案" |
| H1.5 | `finish_check` | `true` | 模型要结束时检查一次：改过文件但之后没跑过任何命令，提醒先验证；一个文件都没改，提醒确认是否需要修改。每种提醒每次运行最多一次 |
| H1.6 | `max_observation_chars` | `10000` | 单个工具结果超过上限时保留开头和结尾，并提示用 grep、`sed -n` 或行号缩小范围 |
| H1.7 | `max_tool_calls_per_reply` | `20` | 单次回复超过上限的工具调用不执行，返回说明（每个调用仍有对应结果） |

所有新提醒都追加在历史末尾，不插到开头，保持提示缓存命中。

## 4. 评测设计

### 4.1 数据划分

- **dev2（开发集）：** 从 SWE-bench Verified 排除试跑（10）与正式样本（100）后的 390 题中抽 100 题，种子 20261030，处理顺序种子 20261030。
- **确认集：** 其余 290 题。本阶段不运行、不查看；最终确认另写预注册。
- 旧的正式样本（100 题）已被多次用于决策，不再用于选择改动。

### 4.2 臂与运行

| 臂 | 配置 | 种子 |
|---|---|---|
| B | C3 + `retry_policy: consecutive`（目前最好的配置） | 101、202 |
| H | B + 第 3 节全部开关 | 101、202 |
| R | mini-SWE-agent 2.4.6，同样设置（参考） | 一次 |

主模型 DeepSeek V4.1 Flash（`deepseek_flash_nothink`）：按量计费、无额度窗口，约 ¥30（含 R）。

### 4.3 分析与决策

- **主分析：** 按题合并两个种子，H 对 B 的解决率差、精确符号翻转检验、按题 bootstrap 区间（`coder_agent.eval.swebench_pooled`）。
- **辅助：** 终止原因去向、成本（输入、调用次数、每解决一题的输入）、与 R 的配对比较。
- **决策（开发阶段，非确认性）：**
  - H − B ≥ +5 pp：做消融（逐项去掉 H1.3、H1.4、H1.1+H1.2，DeepSeek 单种子），再在 GLM 上复核 B 与 H，然后为确认集写预注册；
  - 0 到 +5 pp：按终止原因和轨迹找原因，调整后在 dev2 上重跑一次；
  - 低于 0：逐项消融定位退化来源。

## 7. 风险

- **归因：** H 一次打开多项改动，提升无法直接归到某一项，需要第 4.3 节的消融。
- **模型依赖：** 提示词与预算提醒在 DeepSeek 上有效不代表在 GLM 上有效；GLM 复核不能省。
- **开发集过拟合：** dev2 也会被反复使用；只有确认集上的预注册结果可以对外声明。
- **Rebaseline：** H0 改动 `core/context.py` 与 `core/agent_loop.py`，但只在超长或不合法的历史上改变行为；H1 默认关闭，C3 默认行为不变。按 AGENTS.md 规则在改进报告中说明。
