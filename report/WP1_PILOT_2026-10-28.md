## Infrastructure and protocol findings (fixed)

1. **Wrong GLM key on the host.** The first attempt used a different key.
   Every call got 429 code 1113 ("Insufficient balance or no resource
   package"), and all 10 arm-A patches were empty. Arm R's live preflight
   stopped it before it ran.
   - Fix (`8365c15`): arm A now gets the same check before any container
     starts. One request goes through the Agent's own client, and the
     endpoint must be the Coding Plan endpoint.
   - The invalid attempt was deleted and the pilot rerun from scratch.
2. **Concurrent first open of `run_state.db`.** `django-11490` failed in
   0.7 s with `database is locked` at `PRAGMA journal_mode=WAL`, because
   two workers opened the new database at once.
   - Reproduced on the Mac: 40 trials × 4 threads gave 3 "database is
     locked" and 9 "duplicate column name" errors from the column
     migration.
   - Fixes:
     - `RunStateStore` retries the WAL switch and tolerates a column that
       another connection has just added;
     - the runner shares one store per run, instead of opening one per
       instance and never closing it.
   - 200 trials × 6 threads now run clean, and a regression test fails on
     the old code.
3. **Infrastructure failures were not retried.** The runner retried only
   on a later invocation, and the pilot script calls it once.
   - Fix: with `--retry-errors`, an infrastructure or provider failure is
     rerun once in the same invocation, which is what pre-registration §7
     says.

## Agent behavior seen in the pilot

Pilot instances are excluded from the formal sample, so fixing harness
defects found here does not leak into the formal evaluation. Decision of
2026-10-28: fix 1, 3 and 4 before freezing; leave 2 unchanged.

1. **`patch_file` accepted no-op edits — fixed.** An edit whose `old_text`
   equals its `new_text` used to report `Patched`. In `django-13089` the
   model issued such edits repeatedly, said so itself ("The patches keep
   being written with identical old/new text"), and used all 40 steps and
   280k input tokens before landing the real fix.
   - `patch_file` and `write_file` (edit) now return
     `Error: … is a no-op: old_text and new_text are identical, so nothing
     would change`.
   - This holds in the local and container tools; parity tests assert
     identical output.
   - A rejected edit counts as an ordinary `ToolError` for the unchanged
     retry guard.
2. **The retry guard ends runs on expected failures — unchanged,
   reported.** 5 of 9 runs ended with `max retries (3) exceeded` for
   `AssertionError`, `ImportError` or `ToolError`, yet 3 of those 5 were
   resolved. A failing reproduction or test run before the fix is expected
   on SWE tasks, but the guard counts it as an error streak. Both
   unresolved instances ended this way, and arm R failed them too. The
   formal report gives termination reasons per arm, so this effect stays
   visible.
3. **The container locale was ASCII — fixed.** The Agent saw
   `UnicodeEncodeError` in django tests with non-ASCII file names and
   judged them to be environment failures. SWE-bench containers now start
   with `LANG=C.UTF-8` and `LC_ALL=C.UTF-8` (`SWEBENCH_CONTAINER_ENV`),
   closer to how the harness runs those tests. Arm R keeps
   mini-SWE-agent's default environment.
   - Verified on the host with the `django-11490` image. By default the
     locale is `POSIX`, and Python's filesystem, preferred and stdout
     encodings are `ascii` / `ANSI_X3.4-1968`. With the two variables set,
     all three are UTF-8, and `C.utf8` is installed.
4. **`write_file` without `operation` — fixed.** The dispatcher now checks
   each tool's required arguments before calling it. A call missing one
   gets `Error: write_file is missing required argument(s): operation
   (required: operation, path)` instead of Python's `TypeError` text.
   This applies to every tool, local or container.

Fixes 1 and 4 change shared tool behavior. Under this repository's rule for
`tools/` changes, C3/C4/C6 claims on other lanes need a rebaseline; WP1
establishes its own baseline anyway.
